## JSON 数据格式

每个数据文件是一个对象，包含以下键：

```json
{
  "category": "基础牌",
  "sourceDir": "assets/cards/基础牌",
  "updated": "2026-10-14",
  "cardCount": 76,
  "cards": [
    {
      "id": "basic-001",
      "name": "防御姿态",
      "category": "基础牌",
      "subcategory": "防御",
      "keyword": "普通",
      "faction": "不适用",
      "hp": "不适用",
      "birthplace": "不适用",
      "actionPoint": "1",
      "range": "全地图",
      "target": "单体伤害",
      "cooldown": "未注明",
      "image": "../../assets/cards/基础牌/防御-普通-防御姿态.png",
      "sourceFile": "基础牌/IMG_5980.PNG",
      "transcriptionStatus": "已对照图片转录",
      "ruleStatus": "牌面依据已记录；完整裁定待确认",
      "abilities": ["当别人对你使用“普通牌”时打出，抵挡对方对你的效果。"],
      "userSupplement": ["未记录此牌的单独用户裁定；费用保留要求及通用约束见索引。"],
      "notes": ["“普通牌”的覆盖范围待确认。"]
    }
  ],
  "excludedAssets": [
    { "asset": "../../assets/cards/基础牌/template.png", "sourceFile": "基础牌/IMG_5970.PNG", "handling": "空白模板，无完整卡牌能力" }
  ]
}
```

| 原中文字段/小节 | JSON 键 | 说明 |
|---|---|---|
| ID | `id` | 稳定 ID，一经登记固定保留，不因排序、改名或插入牌重新编号 |
| 名称、类别、子类 | `name`、`category`、`subcategory` | 名称按牌面，类别按原素材目录；基础牌继续区分攻击、防御、锦囊、食物、武器槽和坐骑 |
| 牌面词条 | `keyword` | 按基础牌顶部词条记录；其他类别未印词条则为不适用，不用角色名代替词条 |
| 阵营 | `faction` | 角色/神牌未明确印出阵营，记“未注明”；不凭出生地、名字或阵营牌背反推完整归属表 |
| 牌面血量、出生地 | `hp`、`birthplace` | 记录数字、`?`、`???` 或“未注明”；牌面血量不自行推导为最大生命值 |
| 牌面行动点 | `actionPoint` | 固定值/变量/多档值原样记录；角色的费用见具体技能正文，未写出的费用仍未注明 |
| 范围、对象/牌面标签 | `range`、`target` | 保留“相同/相邻区域”“全地图”“单体伤害”等原表述，治疗牌也不改掉印出的伤害标签 |
| 冷却时长 | `cooldown` | 保存课程的“一回合”“二回合”“无”；未印出的记未注明，不自动补默认值 |
| 来源图片 | `image` | 指向仓库素材，相对 `docs/cards/` 的路径 |
| 对应插画 | `illustration` | 仅选修课，指向该课程的插画 |
| 原始文件（工作区） | `sourceFile` | 保留工作区原始相机/微信文件名 |
| 转录状态、规则状态 | `transcriptionStatus`、`ruleStatus` | 已对照图片转录；完整裁定仍待确认。不是实现状态或可用牌池声明 |
| 能力文本（牌面） | `abilities` | 字符串数组，一条技能一个元素 |
| 用户补充 | `userSupplement` | 字符串数组，通常为一个段落 |
| 待确认与转录备注 | `notes` | 字符串数组，通常为一个段落 |
| 不重复计入卡牌的素材 | `excludedAssets` | 对象数组：`asset`、`sourceFile`、`handling` |

原 markdown 的「卡牌索引」表由 `cards` 数组的 `id`、`name`、`subcategory` 直接替代，不再单独保存。

字段取值保持原样，不做解释性改写：`未注明` 表示图片缺失该信息；`不适用` 表示这个类别没有该类牌面字段；`见能力文本` 表示分技能的数值不能合并为单一属性。不能把这些文字转换成 0、免费、无限、默认出生地或默认阵营。

能力正文保留所有技能，包括主动技、锁定技、被动技和神的陨落，以及课程的小字补充条款。多条能力分项列出，整理换行、标点及编号；不依据“通常玩法”改写技能类别、删掉矛盾条款或补规则。遮蔽名称中的星号原样保留；个别缺少技能名称的条目用“未命名”标记。

## 各类别转录说明

- **通用。** 来源为仓库 `assets/cards/` 中对应类别的图片；以直接读图为主，OCR 辅助查漏。按牌面转录，整理换行和标点，保留原有技能类型、例外、公式及缺项。转录完成不代表完整规则已确认、内容已实现或已进入正式牌池。
- **基础牌。** 用户要求多档及负数行动点费用先保留牌面写法，不推定选档方式、骰子费用或负费用收益。正文中的“单体伤害”“群体伤害”是牌面标注，治疗、控制、地形牌也保留这一标签，不自行更改类型。
- **角色牌与神牌。** “牌面血量”记录右上角印出的数字/符号，不自行推导生命上限。阵营未在这些牌面明确印出，统一记“未注明”；不凭角色名、出生地或牌背推断。主动、被动、锁定和神的陨落标签按原图保留，即使正文看起来是另一种触发方式。
- **神牌。** 神牌未印出出生地，统一记“未注明”。“神的陨落”保留在独立能力条目内，含觉醒、首次归零等特殊触发，不统一改成“最终死亡”。
- **选修课。** 8 门课程各有一张说明图和一张对应插画；插画附在 `illustration` 中，不重复算作课程。小字补充条款全部保留。牌面“冷却时长：无”仅记录原文，不解释为可无限主动使用。未印行动点费用的课程不默认为免费；通校明确写“不用消耗行动点”。

## 来源与当前会话补充

- 主要来源为 `assets/cards/基础牌/`、`角色牌/`、`神牌/`、`选修课/` 的图片；直接读图转录，OCR 仅辅助查漏与对照，不直接作为最终文本。
- 仓库图片和工作区同类别的原始图片按 SHA-256 逐一匹配，确认全部 170 张都有对应原图；转录条目保留原文件名。
- [咖啡](基础牌.json)（`basic-015`）和[橡胶](基础牌.json)（`basic-016`）的素材文件名使用“帝汝”，牌面顶部词条为“帝汶”；登记时按牌面记词条，图片文件名没有改动。
- 用户于 2026-10-14 要求多档和负数行动点费用先保留牌面写法。因此 `/` 或 `1-6` 不自动解释为掷骰、任选或某个默认数值，负数不自动解释为获得行动点。
- 用户于 2026-10-14 明确 [LMM](基础牌.json)（`basic-026`）的“若此作”意为“如果这样做”；强制选中的完整范围仍未另外裁定。
- 用户于 2026-10-14 确认[南帝汶](角色牌.json)（`character-030`）的同步方向：对方扣血/回血同步到南帝汶，南帝汶的回血同步到对方，南帝汶的扣血不影响对方。原文保留，解释列在用户补充中。
- 用户于 2026-10-14 要求[朱伟岩](角色牌.json)（`character-052`）和[水母](角色牌.json)（`character-036`）的缺失参数先标“未注明”；已在[开发方案](../网页游戏开发方案.md)登记。

总规则和历史来源以 [rule.md](../rule.md)、[rule-decisions.md](../rule-decisions.md) 为准。若牌面、总规则、成员回复、用户补充存在冲突，保留各来源并请求裁定，不自动决定优先级。

- 生命上限改变、无上限角色、百分比与小数取整、致命伤害、救援、复活、神的陨落与最终淘汰。
