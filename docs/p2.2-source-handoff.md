## 可直接交给 WorkBuddy

本次请使用 **0.2.1-p2.2** 的两个ZIP，不要复用0.2.0-p2.1源码。新源码配套schema2与web-v0.1.2，包含第一批布局与第二批交互，以及最新Issue建议。

已有schema1数据库先保留快照，只执行新SQL包的 `install-one-statement.sql`，不要重新安装000—004，也不要清空既有房间。再执行 `verify.sql`，预期schemaVersion=2，五个公开RPC可调用，私有表/函数权限拒绝。全新测试库才安装源码中的000—007。

源码ZIP解压后，以包含package.json的目录为应用根目录，沿用相同应用与域名的publicConfig：

```text
installCmd: npm ci && npm run build
startCmd: npm start
```

服务读取PORT并监听0.0.0.0；同端口提供静态页面、健康检查、Socket.IO长轮询及可选WebSocket升级。运行时支持Node22.12+（22.x）或24.x；Node22.13.1已有本地兼容证据。

新旧网关就绪检查分别要求schema2/schema1，SQL和应用需要协调切换，中间`/ready`可能暂时503。完成后`/health`应报告version=0.2.1-p2.2，`/ready`应200。旧局继续原web-v0.1.1，新局使用web-v0.1.2。

请先在隔离环境验证四玩家加观众、双向聊天、三敌人群体牌、头锤吸完AP、弃牌20秒、主动出牌立即重置60秒、移动结束扣费、同码再开与断线/重启恢复，再返回实际报告。本地启动验证只证明包能启动，不声称schema2云端已执行或新增功能已云端验收。
