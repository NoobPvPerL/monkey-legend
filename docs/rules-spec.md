# P0 规则规格

版本：2026-10-15。状态：部分规则已确认的规格草案，不是完整可执行规则集，也不是游戏实现。

依据：[规则汇总](rule.md)、[来源记录](rule-decisions.md)、[工作室群裁定](https://github.com/NoobPvPerL/monkey-legend/issues/1#issuecomment-6183553722)。原始卡牌正文仍以 [卡牌资料](cards/README.md) 为准。本文件不补定牌面缺项。

## 1. 术语与身份

- 对局：从初始化到胜利/平局结算的一局。
- 整轮：普通情况下，全体存活玩家按固定顺序各轮到一次自己的行动时段；插队可中断并开启新轮。
- 个人行动时段：轮到一名玩家的操作时段，不等于只允许打一张牌。
- 初始角色阵营、当前阵营、对局队伍分开保存；它们如何在改阵营牌等情况下同步，仍需 #6 裁定。
- “待确认”不能解释为 0、免费、无限、任意目标或默认概率；只能阻止依赖它的具体内容进入正式规则集。

## 3. 普通阶段与必要停点

```text
初始化（人数、角色池、出生、牌堆等参数必须已确认）
  → AP=5、初始手牌4
整轮开始
  → 全员条件加点（R-008）
  → 环境更新
  → 环境伤害及相应触发（死亡/救援顺序待 #6）
个人行动时段循环
  → 首轮跳过常规补牌；其他轮仅当前玩家抽2
  → 当前玩家行动/响应
  → 自己行动结束后的手牌检查与自选弃牌
  → 交给下一名玩家
普通整轮结束 → 下一整轮
```

- 开局或补牌后暂时超过普通手牌上限，不自动裁剪；其他人的行动中血量下降也不触发普通即时弃牌。
- “结束技能”“美丽学子结束摸牌”“弃牌”“淘汰/救援”的相对顺序未齐，不能根据此总流程自行确定。
- 第 4 轮触发中立选阵营，插队导致的新轮参与计数。选择阶段在加点/环境前后、断线如何等待、选择后胜利检查见 #6；不能自动替玩家选方。
- 插队仅确认结束当前轮并从插队者开启新轮；被中断响应、弃牌、角色次数及环境/首轮例外的完整重置仍待确认。

## 4. 计算与操作示例

普通加点：`AP_next = AP + 3 if AP < 5 else AP`。例：1→4，4→7，5→5，8→8。特殊效果提供的 8 点不因普通阶段变成 7。

普通结束检查：对仍参与该阶段的存活玩家，`limit = floor(current_hp)`；超限数量为 `max(0, hand_count - limit)`，由玩家选弃对应数量的实体卡。此表达不是所有时点都持续维持的约束。

例：血量 2.5、行动开始抽后有 5 张，可以先行动；结束仍有 5 张时，上限 2，选弃 3 张。首轮不补牌，但仍在自己行动结束后检查上限。

## 6. P0 交付与验收边界

素材可定位、规则有来源和案例、未决项有负责人/Issue，是本轮资料交付标准。只有首版所有必要参数与技能裁定确认后，才能把首版 P0 标为通过。静态检查不代替真实对局与游戏测试，见 [案例表](p0-acceptance-cases.md)。
