## P3进入方式

1. 阅读[P3交接](p3-handoff.md)、[遗留待办](p3-backlog.md)和docs/AGENTS.md，核实最新Git／规则／线上信息。
2. 优先复核应豪两项历史反馈，区分已复现缺陷与缺失现场；提交具体修复方案，不用阶段验收推断它们已经修好。
3. 将53条原始角色资料与当前16角色白名单逐ID比较，形成剩余37条候选差距表；有转录／来源不确定的字段保留“待确认”。资料总数不等于已批准全量上线。
4. 提交首批角色建议及完整技能、费用、目标、时限、交互、组合风险，列出文件、兼容影响和验收方式；等负责人明确批准再实施。当前交接不自动批准新增角色名单或改规则。
5. 每批按TS规则核心＋数据库权威实现＋UI操作＋增量迁移＋文档＋组合回归交付。先提供PC／手机截图审核，批准后构建WorkBuddy包，再上传GitHub；生产迁移、部署仍须对应授权。

3—6人／3v3、#812A32主题色是未实施建议，需单独范围设计；神牌16条与课程8条保留P4。不自动启用未批准角色、神牌或课程。

- 客户端只提交意图；权威费用、随机、时钟、合法性、身份与状态在数据库。不能上传可信完整state或通过UI代算权威结果。
- 旧局与已开始选角使用保存版本；000—021迁移及旧目录冻结。后续新增迁移／规则须先核实编号，不覆盖021或复用此前应豪草案中的v10编号。
