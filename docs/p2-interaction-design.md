## 2. 移动防误触

### 2.1 操作流程

1. 玩家点击“移动”，数据库检查本回合未使用基础移动、当前 AP 至少为 1。
2. 数据库掷骰并记录结果，立即消耗本回合移动次数，进入选路阶段；此时暂不扣 AP。
3. 界面显示实际骰子结果、可用步数及“移动完成后扣 1 AP”。
4. 玩家逐步点击合法格子；数据库继续按照现行路径、步数、水域和占位规则校验。
5. 尚未实际迈出任何一步时，显示“取消移动（不扣 AP）”；取消后回到行动阶段，本回合不能再次掷骰移动。
6. 迈出至少一步后，按钮为“结束移动（扣 1 AP）”。额度耗尽、主动结束移动、结束行动或超时收尾，均只扣一次。

### 2.2 状态与结算

- 数据库保存移动起点、已走路径、最近空落点和待结算费用，不由客户端上传是否应收费。
- 是否已经移动依据成功提交的路径步数判断；走出后再返回起点，仍算走过，需扣费。
- 移动阶段不允许出牌或其他消耗 AP 的主动操作，保持现有移动阶段约束。
- 路径非法、网络重发、重复停止请求不重复扣费；沿用命令 ID 幂等机制。
- 经过占用格后超时，仍退到最近已确认的空格；只要此前走过，收取 1 AP。
- 仅掷骰未走即超时，按已确认边界不扣 AP，移动次数仍已使用；此边界已批准。
- 断线、页面接管和进程恢复后，继续原移动状态及原计时，不重新掷骰。

### 2.3 规则版本与兼容

此项改变 web-v0.1.1 的费用时点，新开联机对局采用 web-v0.1.2。部署时已经开始的旧规则对局，继续按其原规则完成；不得追溯退还已扣费用。

TS 引擎与 SQL 引擎均按对局保存的规则版本处理，新旧规则分支须有对应案例。数据库以新增升级迁移交付，保留旧命令回执和历史记录，不要求线上清库或重新安装初始迁移。

### 2.4 验收

- 掷骰后取消、走一步后停止、走回起点、额度耗尽、直接结束行动均符合上述扣费规则。
- 无步移动超时、经过占用格超时、断线超时及进程恢复后结算均正确。
- 相同命令重发不重复掷骰或扣费。
- 新旧规则对局在同一升级后环境中分别完成，TS/SQL 对照一致。

## 3. 房间文字聊天与弹幕

### 3.1 玩家操作

- 联机房间和对局中提供聊天按钮；打开后查看记录、输入并发送文字。
- 消息同时进入聊天记录，并按反馈要求从左向右飘过战场。
- 观众可以发言，姓名旁标注“观众”；玩家标注座位。
- 聊天记录与战斗日志分别展示，战斗提示优先；弹幕避开手牌与操作按钮，点击穿透。
- 提供关闭弹幕选项，关闭后仍能阅读聊天记录。减少动态效果偏好下，采用静态消息提示。

### 3.2 已采用参数

| 参数 | 已采用值 |
|---|---|
| 单条长度 | 去除首尾空白后 1—200 个 Unicode 码点；拒绝控制字符 |
| 单身份发送频率 | 最快每 2 秒一条；数据库侧约束 |
| 默认拉取 | 最近 50 条，之后按消息序号增量同步 |
| 房间记录 | 最多保留最近 200 条；房间关闭后最多保留 24 小时 |
| 弹幕 | 最多 3 条同时显示，每条约 6 秒；超出部分只进入记录，不阻塞操作 |

### 3.3 数据与协议

- 使用独立聊天 RPC、消息表及消息序号，不把聊天写入游戏命令、规则事件或游戏 revision。
- 作者身份由数据库根据已绑定的玩家或观众凭据确定，不接受客户端自报作者、角色或座位。
- 文本以普通文字渲染，不解析 HTML、脚本或任意富文本。
- 发送前生成并保存消息请求 ID；丢失响应时重试原 ID，数据库返回同一条消息，避免重复弹幕。
- 网关通过轮询增量同步并通知客户端，继续兼容 polling-only 连接；重连只补记录，不重播历史弹幕。
- 聊天不消耗 AP、不暂停时钟、不清空准备状态，也不改变游戏命令版本。
- 数据表仍处于私有 schema，仅通过校验房间凭据的入口读写。

### 3.4 验收

四名玩家及观众互发、频率和长度边界、同名身份标识、跨房间隔离、丢响应重试、刷新恢复、关闭弹幕、长消息与手机软键盘均需验证。聊天期间游戏计时和出牌继续正常。

## 4. 观战席

### 4.1 入场与界面

- 进入网页仍先确认玩家名，再输入 4 位房间码。
- 普通加入遇到“已开局”或“玩家已满”时，提供“进入观战”按钮；采用明确点击入场，避免玩家误以为已取得座位。
- 观众不占四个玩家座位，不参与准备、分队、选角或房主转移。
- 显示观众数量及可展开名单；玩家可看到“观战者可查看全部手牌”的信息。
- 观战界面可以查看公开棋盘、日志、结算及四人的完整手牌，不显示出牌、响应、移动、准备或开始按钮。
- 玩家各自的普通对战页面继续只接收本人的手牌；完整手牌仅由独立的观战视图返回。

### 4.2 身份与生命周期

- 观众拥有独立凭据和身份类型，不使用伪造座位或玩家凭据访问。
- 凭据绑定房间 UUID；四位码复用时不能恢复到另一个房间。
- 允许刷新和断线恢复观战；原房间再开一局时继续观战。
- 房间关闭后观战凭据失效。观众不会延长无人玩家房间的关闭期限。
- 同名冲突及容量：玩家与观众共享不区分大小写的名字空间；每房间最多 32 名观众。均随本批批准采用。
- 对局结束后不自动将观众转为玩家；若有空位，要求显式离开观战再按普通规则加入。

### 4.3 数据和接口

- 新增只允许观战的 attach/恢复入口与观战快照类型，类型上明确区分玩家和观众。
- 观众记录在独立私有表；观战连接不写入玩家成员、准备和游戏状态。
- 观战视图在数据库内生成，仅包含获准的四人手牌及公开状态，不返回未来牌堆顺序、随机状态、玩家恢复凭据或内部任务队列。
- 数据库和网关均拒绝观众提交游戏、准备、模式、开始及玩家离开命令；不能仅依靠隐藏按钮。
- 观众加入、退出和聊天采用独立社交状态序号，不清空准备，也不使合法游戏命令因聊天而失效。

### 4.4 验收

已满/已开局入场、四人手牌完整展示、普通玩家视图仍私密、观众命令被拒绝、跨房间访问失败、凭据接管、刷新恢复、同码新房拒绝旧凭据、原房间再开及房间关闭均需验证。

## 5. 骰子与发牌动画

- 骰子动画使用数据库已经产生的真实结果，不在浏览器生成决定游戏状态的随机数。
- 骰子动画 800 毫秒；结果和可操作状态立即可用，动画不能暂停或延长 60 秒/10 秒时限。
- 发牌动画 1.2 秒，显示四人座位与发牌过程；普通玩家只翻开自己的手牌，观众可按已批准的观战范围查看全部手牌。
- 只在当前连接收到新 matchId 的开局时播放发牌动画；刷新、恢复或历史快照不重新播放。
- 使用 matchId 加事件序号去重；重复快照、重连补发不重播骰子。
- 提供跳过或关闭动画方式；减少动态效果偏好下直接显示结果。
- 动画不遮挡选目标、响应和结束行动按钮，不依赖动画完成后才允许操作。

验收覆盖真实结果一致性、重复快照、开局恢复、连续骰子事件、低高度屏幕、减少动态效果偏好及选择计时不被延长。
