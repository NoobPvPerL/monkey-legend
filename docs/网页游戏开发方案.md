# 应猴传说网页版开发方案

方案日期：2026-10-15；状态更新：2026-10-16。规则仍为[web-v0.1.1](web-rules-v0.1.md)。P1本地工程、规则核心、页面与开发验证已完成，本次增加成员本地预发布。本文保留工程设计路线，当前进度以[plan.md](plan.md)、[实现说明](p1-implementation.md)和[开发日志](development-log.md)为准；负责人验收及公网联机尚未完成。

## 1. 产品与范围

四人校园地图回合制卡牌战棋，支持各自为战和2对2。32格、15个地点、四角色、十二种64张牌，目标20—30分钟待实测。
[首版范围](mvp-scope.md)是运行白名单；原始153条内容/187图是资料库，不等于都可用。角色原始阵营与本局队伍分开；不启用中立加入、插队、装备/坐骑、神牌、课程、复活等。
负责人授权规划网页版，成员意见与原作差异记录于 [rule-decisions.md](rule-decisions.md)，本方案不继续等待已关闭#4/#5/#6回答。

## 2. 用户流程与桌面界面

创建/加入房间 → 选择模式并准备 → 系统分配角色/队伍/首位 → 发牌出生 → 顺序行动及响应 → 环境推进 → 胜负排名 → 再开。
P1先做本地测试桌，P2才有独立客户端房间；隐私验收不由本地交接遮罩替代。

桌面顶部展示轮次/当前行动者/剩余时间/连接与环境；左侧四人生命/护盾/AP/队伍/手牌数；中央32格棋盘与区域边界/危险提示/路径；右侧卡牌/角色细节和事件日志；底部自己手牌、移动与结束。
合法范围高亮依当前权威状态更新，区分“格子距离”“区域范围”“移动步耗”，水域不把攻击距离加倍。
公开下一次轰炸与缩圈，目标/费用/超时行为在操作处直接说明。未启用扩展不在可用菜单中显示为可操作。

## 3. 工程路线

| 部分 | 计划路线 | 边界 |
|---|---|---|
| 规则核心 | 独立TypeScript状态/命令/事件模块 | 不依赖UI/网络/真实时钟，注入随机与时钟以便复现 |
| 页面 | React + TypeScript + Vite | 版本已在P1核对并锁定，见package-lock.json |
| 棋盘 | CSS Grid及SVG覆盖层 | 地点ID/地形/毒圈分别建模，原图只作美术参考 |
| 房间服务 | Node.js + Socket.IO | P2实现，服务端判定/串行化/去重，不信任客户端伤害与骰子 |
| 持久化 | 单实例起步，快照和事件可用SQLite | P2明确并验证恢复语义；无需先做多实例 |
| 验证 | 规则测试、可控随机重放、浏览器多客户端检查 | P0只有文档静态核对，P1/P2才真正执行 |

未来目录建议：apps/client、apps/server、packages/game-core、packages/game-data、tests。位置及脚本在P1按项目实际批准建立，不在本次空建工程。
卡牌原文格式及PR #3不在本轮范围；运行数据必须区分原始定义、web-v0.1.1覆盖与实体份号。原始图片不改；P1已按台账生成16份游戏内参考副本。

## 4. 核心状态与流程

实现索引 [W-01—W-10](rules-spec.md)；引擎依其规范处理：校验 → 支付 → 收集响应 → 随机判定 → 伤害批次/淘汰 → 存活者触发 → 清理 → 胜负。
不能在群体伤害中按UI动画先后提前判胜，也不能把环境伤害在每个人回合重复执行。

状态覆盖固定座位/首位、规则版本、阶段、身份/队伍、地图、生命/AP/护盾、五类牌区（抽/弃/结算/各手牌）、移动中状态、响应、每轮技能与个人回合计数、伤害/击杀/淘汰批次、环境和计时。
正式命令接收必须串行，版本/命令ID重复不重复扣费。普通非法命令不改状态，不刷新剩余时间。超时事件与命令在同一事件序列内排序。
所有首版数值为整数，生命上限与AP规则不能从原始复杂牌推断；若扩展半血/百分比，另订单位与取整规则。

## 5. 联机与隐私

P2的客户端只提交意图；服务端负责牌堆、骰子、范围、计时与伤害。每人专属视图只发本人手牌和其他公开状态，不发对手手牌、未来牌堆、随机种子。
刷新/断线恢复同座位、待响应状态及原剩余时限；断线不暂停、不自动投降。60秒行动/10秒选择和超时代弃由W-10定义，不能工程阶段自行改成无限等待。
本地遮罩的局限在启动说明明确，不能声称四人共屏已满足好友私密联机。

## 6. 阶段与验收

[P0完成记录](p0-acceptance-cases.md)与[进度计划](plan.md)为证据入口。
P1：完整规则核心+本地操作+两模式实际对局，逐例核对48个规格场景并覆盖所有角色/牌。
P2：多人房间、独立客户端、私密数据、命令重发/过期拒绝、断线重连与超时。
P3/P4：逐批设计并接入更多内容，包括地形、回合/阵营变化、复活/课程等；资料未知不能偷偷补默认。
P5：手机与加载优化、真实朋友试玩、平衡迭代、部署/恢复说明、发布验收。发布目标另行确认，本次不发布网站。

## 7. 风险与未实测项

四角色强弱、出生点、先手、全图操牌、头锤行动点转移、护盾/补给比例、六格终局与团队比例判分均需实际数据。轰炸按区域均匀意味着大区域覆盖格多，这是已定设计但不表示公平性实测通过。
60秒/10秒是可执行初值，20—30分钟不是由12轮直接推导的保证；响应与选择会增加局长。
P0不依赖完整原作阵营表和高级机制缺项，但启用对应扩展时仍须解决。部署、手机和真实试玩属于后续任务，不冒充首版P0阻塞。
