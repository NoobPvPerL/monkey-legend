## 已实现的判定基础

`packages/game-core/src/p3-h-active.ts`与`database/engine/p3-h-active.sql`只判断当前角色被哪名011封禁。H之外返回无封禁；在图存活011对同地区的其他敌方生效，双人同盟队友不封，各自为战不因队伍字符串相等豁免。地区按区域名称比较，不要求同一格。来源／目标死亡或暂离场停用；梅梅涛的他人角色技能免疫保留；谢bro的主动技免疫不阻止此锁定技。

上述判定现由技能入口、action投影、费用、响应、改骰及资源调用方复用。隔离安装器加载SQL辅助函数并继续撤销公开角色调用权限；不生成030、不改健康端点。`tests/p2/p3-h-active-policy.test.ts`的16项覆盖同区不同格、邻区／远区、队友／敌人、两种免疫、死亡／离场、自己、旧G、正常目录关闭及权限；`p3-h-011.test.ts`新增38项实际接入与组合对照。

## 画圆已接入的边界

暂定费用0AP、每个人回合一次、持续至自己下次开始、固定发动地区及相邻地区，30秒决定是否付1AP豁免本条位移链；这些仍是待醒后验收推断。

| 路径 | 已定位入口 | 完整接入要求 |
|---|---|---|
| 基础移动／冲撞 | `walkClassic`、`applyCollision`、`legalSteps` | 预检整段路径不得扣费或弹窗；正式越界前暂停，付费后续接原剩余路径。冲撞须先检查受推者，不能让推动者先进入尚未腾空格 |
| 通用强制／传送 | `stage3Relocate`、`board-step`及E恢复任务 | 序列化原来源、目标、根链和落点；拒绝只阻止位移，不吞掉原伤害／资源部分。落点在恢复时复检 |
| 交换／肘击跟进 | `p3-e`的`e-swap`／`e-elbow` | 两人都须先通过边界／猴十八／干枯，再开始成对变更，避免半次交换或稳定重叠 |
| 移出地图 | `e-off-map` | 明确视为跨出区域；许可／拒绝可持久化，不能绕过圈或无限询问 |

| 水域跨越 | `relocationCell`、干枯、哈基米路径 | 看真实离开边界的经过路径与落点；同根链收费一次，不先消耗无法执行的骰／AP |
| 超时／存档 | 选择恢复、内部catch-up | 30秒拒绝或按暂定默认，保留原60秒预算；客户端只发意图，TS／SQL完整状态对照 |

按N-08记录并实现：圈包含自己／队友和后来进入者；来源淘汰停用，来源暂离场保留，自己下次开始清理；圈外进入不收费，再离开时判定。每圈／每角色／每原始位移链独立许可，多个圈分别付费。普通无AP、拒绝／超时、JSON恢复及猴十八／水母前置窗口都有对照；多圈与后续050共享坐骑仍须追加组合测试，不冒称所有未来H交互已覆盖。
